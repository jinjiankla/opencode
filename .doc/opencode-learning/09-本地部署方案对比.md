# 本地部署方案详细对比

## 🤔 你的疑问

**问题**：你说的"本地部署"好像也只是改改 URL，难道本地部署比"本地部署+内网模型"更简单一些吗？

**答案**：是的！确实存在这个误解。让我详细解释不同方案的区别。

---

## 📊 三种"本地"方案对比

### 方案 A: 云端 PageIndex（最简单）

```json
{
  "mcp": {
    "pageindex": {
      "type": "local", // ← 这里的 "local" 指 MCP 服务器在本地
      "command": ["npx", "-y", "@pageindex/mcp"]
    }
  }
}
```

**实际架构**：

```
你的电脑（本地）
├── OpenCode CLI
└── MCP 服务器（本地运行）
    ↓ 通过网络
云端（PageIndex 服务器）
├── PDF 处理
├── 树结构生成
└── GPT-4o（OpenAI）
```

**"本地"的含义**：

- ✅ MCP 服务器在本地运行
- ❌ PDF 处理在云端
- ❌ 大模型在云端
- ❌ 数据会上传

**复杂度**：⭐（最简单）
**配置时间**：5 分钟
**需要写代码**：❌ 不需要

---

### 方案 B: 本地 PageIndex + 云端大模型

```json
{
  "mcp": {
    "pageindex-local": {
      "type": "local",
      "command": ["python3", "mcp_server.py"],
      "environment": {
        "OPENAI_API_BASE": "https://api.openai.com/v1", // ← 云端 API
        "OPENAI_API_KEY": "sk-your-openai-key"
      }
    }
  }
}
```

**实际架构**：

```
你的电脑（本地）
├── OpenCode CLI
├── MCP 服务器（本地）
├── PageIndex 核心（本地）
│   ├── PDF 解析（本地）
│   └── 树结构生成（本地）
└── ↓ 通过网络
云端（OpenAI）
└── GPT-4o API
```

**"本地"的含义**：

- ✅ MCP 服务器在本地
- ✅ PDF 处理在本地
- ✅ 树结构生成在本地
- ❌ 大模型在云端（OpenAI）
- ⚠️ PDF 不上传，但会发送文本内容给 OpenAI

**复杂度**：⭐⭐⭐（中等）
**配置时间**：1-2 小时
**需要写代码**：✅ 需要（MCP 服务器）

---

### 方案 C: 本地 PageIndex + 内网大模型（你的需求）

```json
{
  "mcp": {
    "pageindex-enterprise": {
      "type": "local",
      "command": ["python3", "mcp_server.py"],
      "environment": {
        "OPENAI_API_BASE": "http://internal-llm.company.com:8080/v1", // ← 内网
        "OPENAI_API_KEY": "sk-company-key"
      }
    }
  }
}
```

**实际架构**：

```
你的电脑（本地）
├── OpenCode CLI
├── MCP 服务器（本地）
├── PageIndex 核心（本地）
│   ├── PDF 解析（本地）
│   └── 树结构生成（本地）
└── ↓ 通过内网
公司内网（局域网）
└── 大模型服务（Qwen/GLM/等）
```

**"本地"的含义**：

- ✅ MCP 服务器在本地
- ✅ PDF 处理在本地
- ✅ 树结构生成在本地
- ✅ 大模型在内网（不出公司）
- ✅ 数据完全不出内网

**复杂度**：⭐⭐⭐（中等，与方案 B 相同）
**配置时间**：1-2 小时
**需要写代码**：✅ 需要（MCP 服务器）

---

### 方案 D: 完全本地（含本地大模型）

```json
{
  "mcp": {
    "pageindex-offline": {
      "type": "local",
      "command": ["python3", "mcp_server.py"],
      "environment": {
        "OPENAI_API_BASE": "http://localhost:11434/v1", // ← 本机 Ollama
        "OPENAI_API_KEY": "ollama",
        "OPENAI_MODEL": "qwen2.5:32b"
      }
    }
  }
}
```

**实际架构**：

```
你的电脑（本地）
├── OpenCode CLI
├── MCP 服务器（本地）
├── PageIndex 核心（本地）
│   ├── PDF 解析（本地）
│   └── 树结构生成（本地）
└── Ollama（本地）
    └── Qwen2.5:32B（20GB+ 模型）
```

**"本地"的含义**：

- ✅ 所有组件都在本地
- ✅ 完全离线可用
- ✅ 数据完全不出本机

**复杂度**：⭐⭐⭐⭐⭐（最复杂）
**配置时间**：1-2 天
**需要写代码**：✅ 需要（MCP 服务器）
**硬件要求**：16GB+ 内存，20GB+ 存储

## 💡 关键发现

```
方案 C（本地 + 内网模型）:
  配置复杂度: ⭐⭐⭐

两者复杂度完全一样！
只是 URL 不同而已！
```

```
方案 A（云端 PageIndex）:

  "command": ["npx", "-y", "@pageindex/mcp"]
```

## 🎯 为什么会有这个误解？

### 误解来源

**我之前说的"本地部署"**可能让你以为：

```
"本地部署" = 简单
"本地部署 + 内网模型" = 复杂
```

**实际情况**：

```
"云端 PageIndex" = 简单（方案 A）
"本地 PageIndex" = 复杂（方案 B/C/D 都一样复杂）

方案 B 和方案 C 的区别只是 URL：
- 方案 B: https://api.openai.com/v1
- 方案 C: http://internal-llm.company.com/v1
```

### 真正的复杂度来源

**不是来自"内网模型"，而是来自"本地 PageIndex"**

```
复杂的部分：
1. ❌ 不是配置内网模型（只是改 URL）
2. ✅ 是部署 PageIndex 核心
3. ✅ 是创建 MCP 服务器
4. ✅ 是配置 Python 环境
```

```json

      "command": ["npx", "-y", "@pageindex/mcp"]
    }
  }
```

#### 2. 数据不能出公司，但可以用 OpenAI API

**推荐**：方案 B（本地 PageIndex + OpenAI）

**为什么选这个**：

- ✅ PDF 文件不上传
- ✅ 只发送文本内容给 OpenAI
- ✅ 配置相对简单（有 OpenAI API 就行）

**配置**：

```bash
# 1. 部署 PageIndex 核心
git clone https://github.com/VectifyAI/PageIndex.git
pip3 install -r requirements.txt

# 2. 创建 MCP 服务器（复制我提供的代码）
# 3. 配置 OpenAI API
OPENAI_API_BASE=https://api.openai.com/v1
OPENAI_API_KEY=sk-your-key
```

**为什么选这个**：

- ✅ 数据完全不出公司
- ✅ 利用公司现有资源
- ✅ 无额外费用
