# OpenCode 项目概览

## 🎯 项目简介

**OpenCode** 是一个开源的 AI Coding Agent，旨在提供一个功能强大、提供商无关（provider-agnostic）的 AI 辅助开发工具。它是 Claude Code 的开源替代方案，具有以下核心特性：

- **100% 开源** - MIT 许可证，完全透明
- **提供商无关** - 支持多种 AI 模型（Claude、OpenAI、Google、本地模型等）
- **LSP 集成** - 内置语言服务器协议支持
- **终端优先** - 聚焦 TUI（Terminal UI）体验
- **客户端/服务器架构** - 支持本地运行和远程访问

## 📊 技术栈

### 核心技术

- **运行时**: Bun 1.3+
- **语言**: TypeScript (ESM 模块)
- **前端框架**: SolidJS
- **TUI 框架**: OpenTUI (基于 SolidJS)
- **桌面应用**: Tauri
- **API 框架**: Hono
- **验证**: Zod schemas
- **构建工具**: Turbo (monorepo)

### AI 集成

- **AI SDK**: Vercel AI SDK
- **支持的提供商**:
  - Anthropic (Claude)
  - OpenAI (GPT-4, GPT-3.5 等)
  - Google (Gemini, Vertex AI)
  - Azure OpenAI
  - AWS Bedrock
  - Cerebras, Cohere, DeepInfra, Groq, Mistral, Perplexity, Together AI, xAI
  - 本地模型（通过 OpenAI 兼容接口）

## 🔑 核心概念

### 1. Agent 系统

OpenCode 内置三种 Agent：

#### **build** (默认模式)

- 具备完整权限
- 可以修改文件、运行命令
- 适合日常开发工作

#### **plan** (只读模式)

- 只读权限，默认拒绝修改文件
- 运行 bash 命令前会询问
- 适合代码分析、探索未知代码库

#### **general** (子 Agent)

- 用于复杂搜索和多步任务
- 内部使用，也可通过 `@general` 调用

### 2. 工具系统 (Tools)

OpenCode 的核心能力通过工具系统实现，每个工具：

- 实现 `Tool.Info` 接口
- 包含 `execute()` 方法
- 使用 Zod schema 进行输入验证
- 支持上下文传递（sessionID, 权限等）

### 3. 客户端/服务器架构

```
┌─────────────────┐
│   TUI Client    │ ← SolidJS + OpenTUI
│   (Terminal)    │
└────────┬────────┘
         │
         │ HTTP/WebSocket
         │
┌────────▼────────┐
│  OpenCode       │ ← Hono Server
│  Server         │
└────────┬────────┘
         │
    ┌────┴────┐
    │  Tools  │
    │  Agent  │
    │   LSP   │
    │   MCP   │
    └─────────┘
```

## 📦 核心包说明

### packages/opencode

核心包，包含：

- **agent/**: Agent 实现和提示词系统
- **cli/**: 命令行接口和 TUI
- **server/**: HTTP API 服务器
- **tool/**: 工具实现（文件操作、代码搜索、LSP、bash 等）
- **provider/**: AI 提供商集成
- **lsp/**: 语言服务器协议集成
- **mcp/**: Model Context Protocol 集成
- **session/**: 会话管理
- **storage/**: 持久化存储

### packages/app

共享的 Web UI 组件，用于：

- Web 应用
- 桌面应用（通过 Tauri）
- 包含核心 UI 逻辑和组件

### packages/sdk

TypeScript SDK，通过 `@opencode-ai/sdk` 提供：

- API 客户端
- 类型定义
- 自动从 server.ts 生成

### packages/plugin

插件系统（`@opencode-ai/plugin`），允许：

- 扩展工具
- 自定义 Agent 行为
- 集成第三方服务

## 🚀 开发流程

### 快速开始

```bash
# 安装依赖
bun install

# 启动开发服务器（在 packages/opencode 目录运行）
bun dev

# 在其他目录运行
bun dev <directory>

# 构建可执行文件
./packages/opencode/script/build.ts --single
```

### 开发工作流

1. **修改代码** - 在对应的 package 中修改
2. **SDK 更新** - 如果修改了 server.ts，运行 `./script/generate.ts` 重新生成 SDK
3. **类型检查** - `bun run typecheck`
4. **测试** - `bun test` 或 `bun test <文件路径>`

## 🎓 学习路径

### 阶段一：基础架构理解（2-3天）

1. 理解项目结构和核心概念
2. 熟悉 Monorepo 架构和依赖关系
3. 了解构建和开发工具链

### 阶段二：核心系统深入（1-2周）

1. **工具系统** - 学习工具的定义、注册、执行机制
2. **Agent 系统** - 理解 Agent 的提示词工程和执行流程
3. **服务器架构** - Hono API 设计、路由、中间件
4. **会话管理** - 会话生命周期、状态管理、持久化

### 阶段三：专项技术（2-3周）

1. **TUI 实现** - SolidJS + OpenTUI 的应用
2. **LSP 集成** - 语言服务器协议的集成方式
3. **AI 提供商** - 多提供商支持的抽象层设计
4. **MCP 协议** - Model Context Protocol 实现

### 阶段四：高级主题（持续）

1. 插件系统开发
2. 性能优化
3. 安全和权限管理
4. 桌面应用和 Tauri 集成

## 🔧 二次开发关键点

### 1. 添加新工具

```typescript
// src/tool/my-tool.ts
export const MyTool = Tool.define({
  id: "my_tool",
  description: "工具描述",
  parameters: z.object({
    // 参数定义
  }),
  execute: async (input, context) => {
    // 实现逻辑
  },
})
```

### 2. 自定义 Agent

- 修改 `src/agent/prompt/` 中的提示词
- 调整 `src/agent/agent.ts` 中的 Agent 行为

### 3. 扩展 API

- 在 `src/server/server.ts` 中添加路由
- 运行 `./script/generate.ts` 更新 SDK

### 4. UI 定制

- Web UI: `packages/app/`
- TUI: `packages/opencode/src/cli/cmd/tui/`
- Desktop: `packages/desktop/`
